# Adrianic Memory Architecture — lineage-preserving archive

This archive is a **project extraction of the memory architecture and its developmental lineage**.

It deliberately does **not** pretend that one late notebook contains the whole system. The project
branched over time: some earlier memory mechanisms were later consumed, simplified, or left behind
while semantic binding/reasoning work continued. This archive keeps the tested pieces separate and
documents how they fit.

## What is here

### 1. `core_primitives/`
The memory mechanisms themselves:

- complex phase-sensitive memory field (`chi`)
- multi-slot addressable bank
- transparent address-confidence / unresolved behavior
- separated recall and learning timescales
- source-of-surprise repair control
- selective permanent commit (`INCLUDE / EXCLUDE / HOLD`)
- consequence-aware replacement and reconsolidation
- source trust, bias correction, provenance/dependency discounting
- explicit `VALUE_UNRESOLVED`

### 2. `developmental_controller/`
The deterministic self-structuring line:

- v3.8 parity-guarded coalition structural plasticity
- v10 informational softwalls / earned capacity
- v11 action-conditioned structural induction

These experiments let internal structure earn survival from measured consequences. They are not
unrestricted architecture invention: the available substrate and candidate operations are still
engineered.

### 3. `relational_sidecar/`
A runnable exact-identity relational memory lane that sits beside continuous/geometric memory.
Includes a smoke test.

### 4. `semantic_lineage/`
The v4.x and v5.x notebooks/code showing how memory was later used for replay, identity binding,
multi-access retrieval, structural paths, endogenous stopping, consequence arbitration, coreference,
progressive recall, and narrow ontology growth.

These are included as **lineage/provenance**, not as proof that every mechanism belongs in the
standalone memory product.

### 5. `evidence_reports/`
The strongest memory-only reports and selected figures.

### 6. `legacy_reference/`
Older integrated code retained for provenance. It should not be treated as the canonical product
implementation.
