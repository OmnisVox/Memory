## 2026-08-03 — Final integration batch: verification → replacement → field recall

Sources:
- `adrianic_evidence_graph_v3.zip`
- `adrianic_causal_ablation.zip`
- `adrianic_field_replacement_gate.zip`

Recovered failures that change the architecture:
1. A nearest stored slot must not be accepted merely because it beats the second-best slot.  Honest addressing requires an absolute distance wall plus a relative margin.
2. Improved verification can change trust without surviving downstream commit/replacement thresholds.  Verification quality and storage quality are distinct causal stages.
3. When capacity is full, absolute candidate value is insufficient.  Replacement must compare the candidate's expected future value against the retained value of the slot that would be destroyed.
4. Averaging robust address vectors is compatible with the recovered field benchmark; arithmetic averaging of damaged complex phase templates is not.  Address state and recall-template state must remain distinct.
5. A candidate may be `ADDRESS_READY` while its topology-sensitive recall template remains `TEMPLATE_UNRESOLVED`.
6. Robust finite-loop winding is a better recall-validation observable than exact global microscopic plaquette equality near amplitude zeros.

Canonical changes:
- `AddressableMemoryBank.max_distance`
- comparative replacement proxies in `SelectiveCommitController`
- `RobustAnchorFilter`
- `DualRepresentationCandidate`
- `finite_loop_winding`
- `CausalAblationLedger` logging schema

Provenance classifications:
- Evidence Graph v3 anchor-filter source: ORIGINAL EXECUTABLE fragment preserved.
- Causal-ablation numerical ledger/results: EVIDENCE ONLY; branch-cloning source was not present in the ZIP.
- Field replacement integration base: ORIGINAL EXECUTABLE fragment preserved.
- Final topology-qualified field results: EVIDENCE ONLY where the exact final runner source was not present.
- Canonical runtime interfaces above: RECONSTRUCTED from surviving source/report/patch with explicit boundaries.

## 2026-08-03 — v5.0 semantic-governance retraction audit

Sources:
- `Adrianic_v5_0_SemanticProposal_ConsequenceGovernance_Results.zip`

  consequence channel is legitimately informative;

- RETRACT the empirical claim that v5.0 demonstrated consequence-based arbitration among
  semantic proposals, including the rescue, shuffled-trust, and grounding-shift claims;
- RETAIN the pre-governance semantic coverage measurement (top-1 ~0.261, top-5 ~0.767);
- DO NOT retract the architecture concept of proposal generation followed by evidence-weighted
  arbitration; that architecture remains uncleanly tested, not disproven.

Propagation lesson:
- the same helper was later centralized in `common_v51.py`, described as a verified base, and
  imported downstream. Shared bases now require an information-flow/leakage audit before they
  may be promoted as canonical dependencies.

v4.9 boundary:

- v4.9 is nevertheless a narrow constructed symmetric-decoy benchmark where consequence is
  intentionally the only informative asymmetry, and must not be cited as independent semantic
